# GitHub Release Notifier

Бекенд-сервіс, який дозволяє підписатися на email-сповіщення про нові релізи будь-якого обраного GitHub-репозиторію.
Коли у підписаного репозиторію виходить новий реліз, сервіс автоматично надсилає лист підписникам.

## 🚀 Технологічний стек
- **Мова:** Golang 1.22
- **Веб-фреймворк:** Chi (роутинг)
- **База даних:** PostgreSQL 15
- **Міграції:** golang-migrate
- **Інше:** Docker, Docker Compose, net/smtp, GitHub API

## ⚙️ Як запустити сервіс

1. **Клонуйте репозиторій** та переконайтесь, що у вас встановлені Docker та Docker Compose на комп'ютері.

2. **Налаштуйте змінні середовища:**
   Скопіюйте файл-приклад для створення власного `.env`:
   ```bash
   cp .env.example .env
   ```
   У файлі `.env` ви можете вказати `GITHUB_TOKEN`, щоб уникнути обмежень (Rate Limits) від GitHub API.
   Якщо ви хочете, щоб сервіс справді надсилав електронні листи, пропишіть налаштування `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD` та `SMTP_FROM`. (Якщо залишити `SMTP_HOST` порожнім, сервіс просто виводитиме листи в консоль).

3. **Запустіть застосунок через Docker:**
   ```bash
   docker-compose up --build -d
   ```
   *При старті застосунок автоматично накотить усі SQL-міграції (таблиця `subscriptions` буде створена сама).*

Сервіс буде доступний за адресою `http://localhost:8080`.
База даних PostgreSQL буде доступна локально на порту `5432`.

## 🧪 Як запустити тести
Система вкрита unit-тестами для перевірки всіх критичних сценаріїв HTTP-хендлерів без потреби підіймати БД.

Для запуску тестів виконайте:
```bash
go test ./internal/handlers/... -v
```

## 📖 Документація API
Опис ендпоінтів та їх контрактів можна знайти у файлі `swagger.yaml` (OpenAPI 3.0 формат).

Основні ендпоінти:
- `POST /subscribe` - Створити нову підписку (валідація формату `owner/repo`, перевірка репозиторію на GitHub).
- `DELETE /subscribe/{id}` - Видалити підписку за унікальним UUID.
